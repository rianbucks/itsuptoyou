# 1 노드·성장 사건 제안 (stage: propose)

`node tools/stage.mjs start {id} propose`

`tools/pipeline/{id}/proposal.md`를 쓴다. 근거는 모두 timeline.json의 행 id(`r012`, 시대 배경 후보는 `e003`·`x002`)로 단다.

## 초기 분류

- 생애 연표에 용도 열이 있으면(`rows[].use`) 그것을 초기 분류로 삼는다: node → 노드 후보, growth → 성장 사건 후보, chronicle → 기록 서술 후보, era → 시대 배경 후보, exclude → 제외. 분류를 바꾸는 행은 '용도와 다르게 쓴 행' 표에 이유와 함께 적는다.
- 용도 열이 없거나 비어 있는 행은 아래 기준으로 직접 판단한다.
- 용도가 있어도 확인 기호 규칙(✗·불확실 연도는 쓰지 않음)이 먼저다.

## 담을 것

1. **figure.json 값**: born, died, deathType(반영 메모), 프롤로그 복선 후보(출생 연도 세계 사건 후보에서 1개, 근거 행), 사망 원인 이견이 있으면 figure.disputed 초안.
2. **인물 전용 특성 3~5개**: 사료에 기록된 경력·사건에서 만든다. 초기 보유 특성과 근거 행.
3. **핵심 분기점 약 10개** (GDD §3): 연도, 제목, 역사대로 선택지(근거 행), 대안 선택지 2개의 방향, 각 선택지의 주 능력치 가중치(합 1), 결과가 남길 플래그. 판정 노드는 13개 이하.
   - 사건형 사망이면 사망 노드를 원래 사망 연도에 둔다.
   - 연장 노드 1개(대체역사, 원래 사망 연도 이후, requires outlived).
   - 이후 상황을 바꾸는 일탈만 교체 노드(replaces)로 제안한다.
4. **사료 성장 사건**: 노드로 쓰지 않은 행 중 본인의 기록된 행동이 있는 시기. 역사적 성향(근거 행)과 대안 성향 1~2개.
5. **기록 서술 후보**: 성장 사건·노드로 쓰지 않은 사실 행. 각 후보에 "이 기록과 충돌할 선택"을 미리 적는다(§4.6).
6. **시대 배경 후보**: 인물이 살던 지역에 영향을 준 사건(출생 다음 해부터).
   - 연표에 시대 배경 후보 절이 있으면 `eraRows`에서 고른다. 참조 행(`ref`가 있는 행)은 생애 연표의 그 행을 근거로 쓴다. 생애 연표에서 용도가 시대 배경인 행도 후보다.
   - 생애 중 절(`section: during`)은 원래 사망 연도까지, 기록 이후 절(`section: after`)은 원래 사망 연도 뒤의 era에만 쓴다. 기록 이후 era는 연장 구간 판에서만 보인다.
   - 기록 이후 절에서는 '달라질 수 있는지'가 `아니오`인 행(`eraUsable: true`)만 고른다(GDD §4.6). `예`·`설계에 따라` 행은 쓰지 않고, 그 시기의 이야기는 연장 노드의 결과 조각으로 대신한다. 제외한 행은 8번 표에 이유와 함께 적는다.
   - 절이 없으면 생애 연표의 다른 주체의 사건 행에서 고른다.
   - 후보마다 '달라질 수 있는지'(`variability`)를 함께 적는다. `yes`는 충돌할 노드 결과와 남길 플래그를, `design`은 어떤 노드·플래그가 생기면 충돌하는지를 적는다. 연표에 값이 없으면 직접 판단해 적는다.
7. **이견 처리표**: 이견 절의 각 항목을 어디에 disputed로 붙일지, 또는 쓰지 않을지.
8. **제외한 행과 이유**: ✗, 불확실 연도, 사생활에 가까운 일(03_figure_criteria R3), 용도가 '제외'인 행 등.
9. **결말 구조 초안**: 실제 역사 결말 1개, 대체 결말 20~30개의 조건 플래그 묶음, 기본 결말.

## 멈춤

제안을 보여주고 승인을 받는다. 승인 전에는 2단계로 넘어가지 않는다.

```
node tools/stage.mjs end {id} propose --counts nodes=노드수,growth=성장사건수
node tools/stage.mjs wait {id} 제안 승인 대기
(사용자 승인 후)
node tools/stage.mjs resume {id}
node tools/stage.mjs approve {id} proposal --by 사용자 --note "승인 메시지 요약"
```

사용자가 수정을 요청하면 proposal.md를 고치고 다시 승인을 받는다(propose 단계를 다시 start/end로 기록).
